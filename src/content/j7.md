Когда нужно создать много однотипных объектов с поведением — пользователей, товары, игровых персонажей — удобно описать «чертёж» один раз. Таким чертежом в JavaScript служит **класс**.

## Класс и экземпляры

```js
class User {
  constructor(name, email) {   // вызывается при new
    this.name = name
    this.email = email
    this.createdAt = new Date()
  }

  greet() {                    // метод: общий для всех экземпляров
    return `Привет, я ${this.name}`
  }
}

const anna = new User('Аня', 'anna@example.com')  // экземпляр
const oleg = new User('Олег', 'oleg@example.com')
anna.greet()   // 'Привет, я Аня'
```

- `class` объявляет чертёж, `new` создаёт по нему объект;
- `constructor` заполняет свойства нового объекта через `this`;
- методы описываются без слова `function` и без запятых между ними.

## Поля, геттеры и сеттеры

```js
class Counter {
  count = 0                 // поле класса со значением по умолчанию
  #step = 1                 // приватное поле: недоступно снаружи

  get double() {            // геттер: читается как свойство
    return this.count * 2
  }

  set step(value) {         // сеттер: срабатывает при присваивании
    if (value <= 0) throw new Error('Шаг должен быть положительным')
    this.#step = value
  }

  increment() {
    this.count += this.#step
  }
}

const c = new Counter()
c.step = 5
c.increment()
c.count      // 5
c.double     // 10
// c.#step   — SyntaxError: приватное поле
```

Приватные поля (`#`) защищают внутреннее состояние: снаружи его можно менять только через методы класса.

## Статические члены

`static` — свойство или метод самого класса, а не экземпляров:

```js
class Temperature {
  static fromFahrenheit(f) {
    return new Temperature((f - 32) * 5 / 9)
  }
  constructor(celsius) { this.celsius = celsius }
}

const t = Temperature.fromFahrenheit(212)  // 100 °C
```

## Наследование

Класс может расширять другой, получая все его свойства и методы:

```js preview
class Animal {
  constructor(name) {
    this.name = name
  }
  speak() {
    return `${this.name} издаёт звук`
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name)           // вызвать конструктор родителя — обязательно до this
    this.breed = breed
  }
  speak() {               // переопределение метода
    return `${this.name} лает`
  }
  info() {
    return `${super.speak()} (порода: ${this.breed})` // метод родителя
  }
}

const rex = new Dog('Рекс', 'овчарка')
console.log(rex.speak())
console.log(rex.info())
console.log(rex instanceof Dog, rex instanceof Animal)
```

## Под капотом: прототипы

Классы — удобный синтаксис над **прототипами**. У каждого объекта есть скрытая ссылка на объект-прототип; если свойства нет у самого объекта, JavaScript ищет его в прототипе, потом в прототипе прототипа и так далее (цепочка прототипов). Методы класса лежат в `User.prototype` — поэтому они не копируются в каждый экземпляр, а разделяются всеми.

Встроенные типы устроены так же: `[1, 2].map` — метод из `Array.prototype`.

## Когда нужны классы

В современном фронтенде классы встречаются реже, чем кажется: Vue с Composition API построен на функциях и объектах. Но классы полезны для моделей данных, сервисов (API-клиент), ошибок (`class ValidationError extends Error`), и их нужно уметь читать в чужом коде и библиотеках.
