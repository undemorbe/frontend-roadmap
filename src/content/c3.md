Что будет, если два правила задают одному элементу разный цвет? Ответ на этот вопрос — **каскад**, первая буква в аббревиатуре CSS. Понимание каскада избавляет от бесконечных `!important`.

## Каскад: кто победит

Когда несколько объявлений спорят за одно свойство одного элемента, браузер сравнивает их по очереди:

1. **Происхождение и важность.** Стили браузера < ваши стили < ваши стили с `!important`.
2. **Слои** (`@layer`) — если используются.
3. **Специфичность** селектора — чем «точнее» селектор, тем он сильнее.
4. **Порядок** — при равной специфичности побеждает то, что написано **позже**.

```html preview
<p class="text" id="intro">Какого я цвета?</p>
<style>
  #intro { color: green; }   /* id — самый специфичный */
  .text { color: blue; }
  p { color: red; }
  p { color: orange; }       /* побеждает p { red } — написано позже */
</style>
```

Абзац будет зелёным: id весит больше класса и тега, хотя написан раньше.

## Специфичность

Специфичность считают тремя числами **(A, B, C)**:

- **A** — количество id;
- **B** — классов, атрибутов `[type]` и псевдоклассов `:hover`;
- **C** — тегов и псевдоэлементов `::before`.

Сравнивают слева направо: один id сильнее любого количества классов.

| Селектор | Специфичность |
|---|---|
| `p` | 0, 0, 1 |
| `ul li a` | 0, 0, 3 |
| `.button` | 0, 1, 0 |
| `.nav a:hover` | 0, 2, 1 |
| `#header .logo` | 1, 1, 0 |
| `style="…"` | побеждает любой селектор |
| `*`, `:where(...)` | 0, 0, 0 |

`:is()`, `:not()` и `:has()` берут специфичность **самого сильного** аргумента; `:where()` всегда даёт ноль.

> [!tip] Совет
> Держите специфичность низкой и ровной: стилизуйте **одним классом**. Тогда побеждает просто правило, написанное ниже, и CSS предсказуем. Id в селекторах и длинные цепочки вроде `.page .content .list li a` — путь к войне специфичностей.

## !important

```css
.alert { color: red !important; }
```

`!important` перебивает обычную специфичность. Это «ядерное оружие»: чтобы перебить его, нужен ещё один `!important` с большей специфичностью. Допустимые случаи — служебные классы вроде `.hidden { display: none !important; }` и переопределение чужих стилей, которые нельзя изменить.

## Наследование

Некоторые свойства **наследуются** — дети получают значение от родителя, если им не задано своё. В основном это свойства текста:

- наследуются: `color`, `font-family`, `font-size`, `line-height`, `text-align`, `visibility`, `cursor`…
- не наследуются: `margin`, `padding`, `border`, `background`, `width`, `display`…

Поэтому шрифт достаточно задать один раз для `body` — и он «стечёт» на всю страницу. А если бы `border` наследовался, рамки были бы у каждого вложенного элемента.

```html preview
<div class="parent">
  Родитель
  <p>Ребёнок наследует цвет и шрифт, но не рамку</p>
</div>
<style>
  .parent { color: #2167c9; font-family: Georgia, serif; border: 2px dashed tomato; padding: 8px; }
</style>
```

## Управляющие значения

Любому свойству можно задать специальное значение:

- `inherit` — взять значение у родителя (даже для ненаследуемых);
- `initial` — исходное значение из спецификации;
- `unset` — `inherit` для наследуемых свойств, `initial` для остальных;
- `revert` — откатить к стилям браузера.

```css
.card a { color: inherit; }   /* ссылка — того же цвета, что текст карточки */
button { font: inherit; }     /* кнопки по умолчанию НЕ наследуют шрифт страницы */
```

## Каскадные слои @layer

Слои позволяют явно упорядочить группы стилей: порядок слоёв важнее специфичности внутри них.

```css
@layer reset, base, components, utilities;

@layer base {
  #app a { color: blue; }   /* даже id здесь… */
}
@layer components {
  .link { color: green; }   /* …проиграет классу в более позднем слое */
}
```

Это удобно для больших проектов и подключения сторонних библиотек.
