Фронтенд почти всегда общается с сервером: загружает товары, отправляет формы, авторизует пользователей. Инструмент для этого — встроенная функция `fetch`. А `localStorage` позволяет сохранить данные прямо в браузере.

## JSON

Сервер и браузер обмениваются данными в формате **JSON** — текстовом представлении объектов:

```json
{
  "id": 1,
  "title": "Выучить fetch",
  "done": false,
  "tags": ["js", "network"]
}
```

Отличия от объекта JS: ключи и строки — **только в двойных кавычках**, нет функций, `undefined`, комментариев и висящих запятых.

```js
const json = JSON.stringify({ a: 1, b: [1, 2] })  // объект → строка
const obj = JSON.parse('{"a":1}')                 // строка → объект
JSON.stringify(data, null, 2)                     // с отступами — для чтения
```

## fetch: GET-запрос

```js
async function loadTodos() {
  const response = await fetch('https://jsonplaceholder.typicode.com/todos?_limit=3')
  if (!response.ok) {                     // fetch НЕ бросает ошибку на 404/500!
    throw new Error(`Ошибка HTTP: ${response.status}`)
  }
  const todos = await response.json()     // тело ответа → объект (тоже промис)
  return todos
}
```

Два `await`: первый — дождаться заголовков ответа, второй — дочитать и разобрать тело. Объект `Response` содержит `status` (200, 404…), `ok` (`true` для 200–299), `headers` и методы чтения тела: `json()`, `text()`, `blob()`.

> [!warn] Осторожно
> `fetch` отклоняет промис только при **сетевой** ошибке (нет интернета, сервер недоступен). Ответ 404 или 500 — это «успешный» ответ с `ok: false`. Проверяйте `response.ok` всегда.

## POST-запрос

```js
const response = await fetch('/api/todos', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ title: 'Новая задача', done: false }),
})
const created = await response.json()
```

Методы HTTP: `GET` — получить, `POST` — создать, `PUT`/`PATCH` — изменить, `DELETE` — удалить. Такой стиль API называют REST.

## Состояния загрузки

Хороший интерфейс показывает **все** состояния запроса: загрузка → данные или ошибка. И пустой результат.

```js
async function showTodos() {
  list.textContent = 'Загрузка…'
  try {
    const todos = await loadTodos()
    if (!todos.length) {
      list.textContent = 'Задач пока нет'
      return
    }
    render(todos)
  } catch (err) {
    list.textContent = 'Не удалось загрузить. Попробуйте позже.'
  }
}
```

> [!info] Как это связано
> Во Vue эти состояния хранят в реактивных переменных `loading`, `error`, `data` — и шаблон сам показывает нужное. Такую логику выносят в composable `useFetch()`.

## CORS в двух словах

Браузер по умолчанию не даёт странице с `site-a.com` читать ответы `site-b.com`. Сервер должен явно разрешить это заголовком `Access-Control-Allow-Origin`. Если в консоли ошибка «CORS policy» — дело в настройках **сервера**, а не вашего кода. Во время разработки помогает прокси Vite (станция «Конфиг Vite»).

## localStorage

Хранилище «ключ — значение» в браузере. Данные переживают перезагрузку и закрытие вкладки. Храниться могут только **строки**, поэтому объекты превращают в JSON:

```js
localStorage.setItem('theme', 'dark')
localStorage.getItem('theme')            // 'dark'
localStorage.removeItem('theme')

// объекты — через JSON
localStorage.setItem('todos', JSON.stringify(todos))
const saved = JSON.parse(localStorage.getItem('todos') ?? '[]')
```

`sessionStorage` — то же самое, но живёт до закрытия вкладки. Объём — около 5 МБ. Не храните там пароли и токены доступа: localStorage доступен любому скрипту на странице.

> [!tip] Совет
> На этой схеме прогресс и ваш код тоже хранятся в `localStorage`. Загляните в DevTools → Application → Local Storage.
