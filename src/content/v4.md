Часто одни данные выводятся из других: сумма корзины — из списка товаров, отфильтрованный список — из исходного и строки поиска. Для этого есть **computed**. А когда на изменение данных нужно отреагировать **действием** (сохранить, отправить запрос, записать в лог) — используют **watch**.

## computed: вычисляемые значения

```js
const items = ref([
  { name: 'Билет', price: 70, qty: 2 },
  { name: 'Карта', price: 300, qty: 1 },
])

const total = computed(() =>
  items.value.reduce((sum, i) => sum + i.price * i.qty, 0),
)

console.log(total.value) // 440
```

Почему не просто функция `getTotal()` в шаблоне? Потому что `computed` **кэшируется**: он пересчитывается, только когда изменились его зависимости (`items`). Функция в шаблоне выполнялась бы при каждой перерисовке компонента.

```html preview vue
<div id="app">
  <label><input type="checkbox" :checked="onlyOpen" @change="onlyOpen = !onlyOpen"> Только открытые</label>
  <ul>
    <li v-for="s in visible" :key="s.id">{{ s.name }}</li>
  </ul>
  <p>Показано {{ visible.length }} из {{ stations.length }}</p>
</div>

<script>
  const { createApp, ref, computed } = Vue
  createApp({
    setup() {
      const onlyOpen = ref(false)
      const stations = ref([
        { id: 1, name: 'Теги', open: true },
        { id: 2, name: 'Формы', open: false },
        { id: 3, name: 'Flexbox', open: true },
      ])
      const visible = computed(() =>
        onlyOpen.value ? stations.value.filter((s) => s.open) : stations.value,
      )
      return { onlyOpen, stations, visible }
    },
  }).mount('#app')
</script>
```

Правила для computed:

- **без побочных эффектов**: не меняйте внутри другие данные, не делайте запросы — только вычисляйте и возвращайте;
- не меняйте исходный массив: `sort()` и `reverse()` меняют массив на месте, используйте `[...arr].sort()` или `toSorted()`;
- результат computed — это ref (в JS читается через `.value`, в шаблоне — без).

Редко бывает нужен **записываемый** computed с `get` и `set`:

```js
const fullName = computed({
  get: () => `${first.value} ${last.value}`,
  set: (v) => ([first.value, last.value] = v.split(' ')),
})
```

## watch: реакция на изменения

`watch` следит за источником и вызывает функцию, когда он меняется:

```js
const query = ref('')

watch(query, (newValue, oldValue) => {
  console.log(`Поиск: «${oldValue}» → «${newValue}»`)
  fetchResults(newValue)
})
```

Источником может быть ref, геттер-функция или массив источников:

```js
watch(() => user.value.id, (id) => loadProfile(id))  // одно поле объекта
watch([a, b], ([newA, newB]) => { ... })             // несколько источников
```

Опции:

```js
watch(settings, save, { deep: true })       // следить за вложенными изменениями
watch(userId, load, { immediate: true })    // вызвать сразу, а не только при изменении
watch(source, cb, { once: true })           // сработать один раз
```

## watchEffect

`watchEffect` сам определяет зависимости — по тому, что прочитано внутри, — и запускается сразу:

```js
watchEffect(() => {
  document.title = `Корзина (${count.value})`
})
```

## computed или watch?

| Задача | Инструмент |
|---|---|
| Получить новое значение из существующих | `computed` |
| Отфильтровать, отсортировать, посчитать | `computed` |
| Сохранить в localStorage при изменении | `watch` |
| Загрузить данные при смене id | `watch` |
| Синхронизировать `document.title` | `watchEffect` |

> [!tip] Совет
> Частая ошибка новичков — хранить вычисляемое значение в отдельном `ref` и обновлять его через `watch`. Если значение можно **вычислить** — используйте `computed`.
