Код почти никогда не работает с первого раза — и это нормально. Профессионала от новичка отличает не отсутствие ошибок, а умение быстро их **найти**. Главный инструмент для этого встроен в каждый браузер — **DevTools** (инструменты разработчика). Пересадка со станции «Функции» линии JS: там вы писали функции, здесь научитесь заглядывать внутрь них во время выполнения.

## Как открыть

- <kbd>F12</kbd> или <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>I</kbd> (на macOS <kbd>⌘</kbd>+<kbd>⌥</kbd>+<kbd>I</kbd>);
- правый клик по элементу → «Просмотреть код» — откроет панель Elements сразу на нём.

Дальше речь о Chrome; в Firefox и Safari панели называются почти так же.

## Elements: живой DOM и стили

Панель **Elements** показывает не исходный HTML, а **текущее** дерево DOM — со всеми изменениями, которые сделал JavaScript.

- двойной клик по тексту или атрибуту — редактирование прямо на странице;
- справа, во вкладке **Styles** — все CSS-правила элемента, перечёркнуты те, что проиграли каскад;
- вкладка **Computed** — итоговые значения свойств (удобно, когда непонятно, откуда взялся отступ);
- кнопка `:hov` включает состояния `:hover`, `:focus` без мыши;
- значки `flex` и `grid` рядом с элементом рисуют сетку поверх страницы.

> [!tip] Совет
> Подбирайте значения прямо в Styles стрелками ↑/↓ (с <kbd>Shift</kbd> — шаг 10), а найденное переносите в свой CSS. Изменения в DevTools пропадут после перезагрузки.

## Console: разговор с программой

**Console** показывает ошибки и всё, что вывел `console.*`, а ещё здесь можно выполнять любой JS в контексте страницы.

```js
console.log('обычное сообщение', user)
console.warn('предупреждение — жёлтое')
console.error('ошибка — красная, со стеком вызовов')
console.table([{ id: 1, name: 'Теги' }, { id: 2, name: 'Формы' }]) // массив объектов таблицей
console.group('Корзина'); console.log('товар 1'); console.groupEnd()
console.time('сортировка'); bigArray.sort(); console.timeEnd('сортировка')
```

Полезные возможности консоли:

- `$0` — элемент, выделенный в Elements; `$('.btn')` — короткий `querySelector`;
- клик по имени файла справа от сообщения — переход к строке кода;
- красная ошибка содержит **стек вызовов**: читайте его сверху вниз — где упало и кто вызвал.

Как читать ошибку:

```text
Uncaught TypeError: Cannot read properties of undefined (reading 'name')
    at renderCard (cards.js:12:24)
    at Array.forEach (<anonymous>)
    at render (cards.js:5:9)
```

Тип (`TypeError`) → что случилось (читали `.name` у `undefined`) → где (`cards.js`, строка 12). Значит, в `renderCard` пришёл `undefined` вместо объекта — смотрим, что передаёт `render`.

## Sources: точки останова

`console.log` хорош, но иногда быстрее **остановить** программу и осмотреться. В панели **Sources** кликните по номеру строки — появится **точка останова** (breakpoint). Когда выполнение дойдёт до неё, программа замрёт, и вы увидите:

- **Scope** — значения всех переменных в этот момент;
- **Call Stack** — цепочку вызовов;
- **Watch** — выражения, за которыми хотите следить.

Кнопки управления:

| Кнопка | Действие |
|---|---|
| ▶ Resume (<kbd>F8</kbd>) | Продолжить до следующей точки |
| ⤼ Step over (<kbd>F10</kbd>) | Следующая строка, не заходя в функции |
| ↓ Step into (<kbd>F11</kbd>) | Зайти внутрь вызываемой функции |
| ↑ Step out (<kbd>Shift</kbd>+<kbd>F11</kbd>) | Выйти из текущей функции |

Точку останова можно поставить и в коде — инструкцией `debugger`. Она срабатывает, только когда DevTools открыты:

```js
function total(items) {
  let sum = 0
  for (const item of items) {
    debugger // здесь выполнение остановится
    sum += item.price * item.qty
  }
  return sum
}
```

Правый клик по номеру строки → **Conditional breakpoint** — остановка только при условии, например `item.qty > 10`.

## Network: запросы

Панель **Network** — список всех запросов страницы: HTML, CSS, картинки, `fetch`. Для каждого видно статус (200, 404, 500), размер, время и содержимое ответа (вкладка Preview). Фильтр **Fetch/XHR** оставляет только запросы к API.

- статус 404 — неверный адрес; 401/403 — нет доступа; 500 — ошибка на сервере;
- **Throttling** («Slow 4G») показывает, как сайт грузится на медленном интернете;
- галочка **Disable cache** — чтобы точно получать свежие файлы.

## Application: хранилища

Панель **Application** показывает `localStorage`, `sessionStorage`, cookies и IndexedDB. Здесь можно посмотреть, что сохранило приложение, отредактировать значение или очистить всё (**Clear site data**) — например, прогресс этого учебника лежит в ключе `frontend-metro:v1`.

## Lighthouse и Vue Devtools

- **Lighthouse** — автоматический аудит: производительность, доступность, SEO, лучшие практики. Запускайте перед публикацией.
- **Vue Devtools** — расширение для браузера (или плагин `vite-plugin-vue-devtools`): дерево компонентов, их props и состояние, хранилища Pinia и история переходов роутера.

## Метод отладки

1. **Воспроизведите** ошибку стабильно: какие действия к ней приводят?
2. **Прочитайте** сообщение об ошибке целиком — чаще всего ответ уже там.
3. **Сузьте** место: выводите промежуточные значения или ставьте точку останова — где данные впервые становятся неправильными?
4. **Исправьте** одну вещь и проверьте снова.
5. Если застряли — объясните задачу вслух (метод «резиновой утки») или сделайте перерыв.
