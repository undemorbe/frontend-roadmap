Когда одни и те же данные нужны многим компонентам (корзина — в шапке, в каталоге и на странице оформления; пользователь — везде), передавать их через props и события по цепочке становится мучением («prop drilling»). Решение — **глобальное хранилище состояния**. Официальное хранилище для Vue — **Pinia**.

## Зачем хранилище

```text
          App                         App
        /     \                     /     \
   Header     Catalog          Header     Catalog
     |           |                 \       /
  CartBadge  ProductCard            [ Store ]
     ↑           ↓                  /       \
  props ← emit ← emit ...     CartBadge   ProductCard
```

Без хранилища `ProductCard` должен отправить событие наверх через несколько уровней, а `App` — спустить данные вниз в `CartBadge`. С хранилищем оба компонента просто обращаются к одному store.

## Установка

```bash
npm install pinia
```

```js
// main.js
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'

createApp(App).use(createPinia()).mount('#app')
```

## Объявление store

Store описывается функцией `defineStore`. Удобнее всего **setup-синтаксис** — он такой же, как `<script setup>`:

```js
// stores/cart.js
import { ref, computed } from 'vue'
import { defineStore } from 'pinia'

export const useCartStore = defineStore('cart', () => {
  // state
  const items = ref([])

  // getters
  const count = computed(() => items.value.reduce((s, i) => s + i.qty, 0))
  const total = computed(() => items.value.reduce((s, i) => s + i.price * i.qty, 0))

  // actions
  function add(product) {
    const found = items.value.find((i) => i.id === product.id)
    if (found) found.qty++
    else items.value.push({ ...product, qty: 1 })
  }

  function remove(id) {
    items.value = items.value.filter((i) => i.id !== id)
  }

  return { items, count, total, add, remove }
})
```

- `ref` → **state** (состояние);
- `computed` → **getters** (вычисляемые значения);
- функции → **actions** (действия, могут быть асинхронными).

Есть и **options-синтаксис**, похожий на Options API:

```js
export const useCounterStore = defineStore('counter', {
  state: () => ({ count: 0 }),
  getters: {
    double: (state) => state.count * 2,
  },
  actions: {
    increment() { this.count++ },
  },
})
```

## Использование в компонентах

```vue
<script setup>
import { useCartStore } from '../stores/cart.js'

const cart = useCartStore()
</script>

<template>
  <button @click="cart.add({ id: 1, name: 'Проездной', price: 450 })">В корзину</button>
  <p>В корзине: {{ cart.count }} шт. на {{ cart.total }} ₽</p>
</template>
```

Store — reactive-объект: refs внутри разворачиваются, `.value` не нужен. Все компоненты, вызвавшие `useCartStore()`, получают **один и тот же** экземпляр.

> [!warn] Деструктуризация
> `const { count, total } = cart` сломает реактивность (как с `reactive`). Используйте `storeToRefs`:
>
> `const { count, total } = storeToRefs(cart)` — а функции-действия можно доставать напрямую: `const { add } = cart`.

## Полезные возможности

```js
cart.$reset()                         // сброс к начальному состоянию (для options-синтаксиса)
cart.$patch({ items: [] })            // изменить несколько полей разом
cart.$subscribe((mutation, state) => {
  localStorage.setItem('cart', JSON.stringify(state.items))  // сохранение при любом изменении
})
```

Store может использовать другой store, роутер, composables — это обычный JS-модуль. А Vue Devtools показывают состояние всех stores и историю действий.

## Когда нужен Pinia

- Данные нужны компонентам в разных ветках дерева.
- Состояние должно жить дольше, чем компонент (при переходе между страницами).
- Нужно отлаживать изменения в Devtools.

Если данные нужны одному компоненту и его детям — хватит `ref` и props.
