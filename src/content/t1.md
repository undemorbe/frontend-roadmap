Коричневая линия — про рабочее окружение. До сих пор код запускался в песочнице, а в реальной разработке вы будете работать в **терминале**, ставить пакеты через **npm** и собирать проект **Vite**. Начнём с основ.

## Терминал

Терминал (командная строка, консоль) — текстовый способ управлять компьютером. Им пользуются, потому что это быстро, воспроизводимо и автоматизируемо. На macOS — приложение «Терминал» (или встроенный терминал VS Code: <kbd>Ctrl</kbd>+<kbd>`</kbd>), на Windows — PowerShell или Windows Terminal.

Самые нужные команды:

| Команда | Что делает |
|---|---|
| `pwd` | Показать, в какой папке я нахожусь |
| `ls` (`dir` в Windows) | Список файлов в папке |
| `cd projects` | Перейти в папку `projects` |
| `cd ..` | Подняться на уровень выше |
| `cd ~` | В домашнюю папку |
| `mkdir my-app` | Создать папку |
| `touch index.html` | Создать пустой файл (macOS/Linux) |
| `code .` | Открыть текущую папку в VS Code |
| `clear` | Очистить экран |

Полезное: <kbd>Tab</kbd> дописывает имена файлов, <kbd>↑</kbd> — предыдущая команда, <kbd>Ctrl</kbd>+<kbd>C</kbd> — остановить запущенный процесс (например, dev-сервер).

## Node.js

**Node.js** — среда, которая выполняет JavaScript вне браузера: на сервере и в терминале. Фронтендеру Node нужен не столько для бэкенда, сколько для **инструментов**: Vite, ESLint, Prettier, тесты — всё это программы на JavaScript, запускаемые Node'ом.

Установка — с [nodejs.org](https://nodejs.org/) (выбирайте LTS — версию с долгой поддержкой). Проверка:

```bash
node -v    # v24.x.x
npm -v     # 11.x.x
```

> [!tip] Совет
> Для работы с несколькими версиями Node используют менеджеры версий: `nvm`, `fnm` или `volta`. Это избавит от проблем, когда старому проекту нужна старая версия.

## npm и package.json

**npm** (Node Package Manager) — менеджер пакетов: устанавливает чужой код (библиотеки) в ваш проект. Реестр npmjs.com содержит миллионы пакетов.

Сердце любого проекта — файл **`package.json`**:

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "dependencies": {
    "vue": "^3.5.0"
  },
  "devDependencies": {
    "vite": "^7.0.0",
    "@vitejs/plugin-vue": "^6.0.0"
  }
}
```

| Поле | Зачем |
|---|---|
| `scripts` | Короткие имена для команд: `npm run dev` запустит `vite` |
| `dependencies` | Пакеты, нужные приложению в работе (Vue, роутер) |
| `devDependencies` | Пакеты только для разработки (сборщик, линтер) |
| `"type": "module"` | Файлы `.js` — ES-модули (`import`/`export`) |

## Главные команды npm

```bash
npm init -y               # создать package.json
npm install               # (npm i) установить всё из package.json
npm install vue           # добавить пакет в dependencies
npm install -D vite       # добавить в devDependencies
npm uninstall lodash      # удалить пакет
npm run dev               # запустить скрипт "dev"
npx eslint .              # запустить утилиту из пакета без глобальной установки
npm outdated              # какие пакеты устарели
```

Пакеты кладутся в папку **`node_modules`**. Она огромная и **никогда** не попадает в Git — её всегда можно восстановить командой `npm install`.

## Версии: что значит ^3.5.0

Версии пакетов следуют **семантическому версионированию** (SemVer): `МАЖОР.МИНОР.ПАТЧ`.

- **ПАТЧ** (3.5.**1**) — исправления ошибок;
- **МИНОР** (3.**6**.0) — новые возможности, совместимые со старыми;
- **МАЖОР** (**4**.0.0) — ломающие изменения.

`^3.5.0` разрешает обновления до `<4.0.0`, `~3.5.0` — только патчи (`<3.6.0`).

Файл **`package-lock.json`** фиксирует **точные** версии всего дерева зависимостей. Его коммитят в Git — тогда у всех в команде и на сервере установятся одни и те же версии. `npm ci` ставит строго по lock-файлу (используется в CI).
