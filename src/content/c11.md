Пока стилей мало, порядок в них не важен. Но реальный проект — это тысячи строк CSS. Эта станция — про то, как писать CSS, который не страшно менять: переменные, методология БЭМ, вложенность и сброс стилей.

## Пользовательские свойства (CSS-переменные)

```css
:root {
  --color-primary: #2167c9;
  --color-text: #17160f;
  --radius: 12px;
  --space: 16px;
}

.button {
  background: var(--color-primary);
  border-radius: var(--radius);
  padding: calc(var(--space) / 2) var(--space);
}
```

- Объявляются с двумя дефисами `--имя`, читаются через `var(--имя)`.
- Второй аргумент — запасное значение: `var(--accent, tomato)`.
- Они **наследуются** и подчиняются каскаду: переменную можно переопределить для части страницы или для состояния.
- В отличие от переменных препроцессоров (Sass), CSS-переменные **живые**: их можно менять в медиазапросах и из JavaScript.

```html preview
<div class="theme">
  <button class="btn">Обычная</button>
  <button class="btn danger">Опасная</button>
</div>
<div class="theme dark">
  <button class="btn">В тёмной теме</button>
</div>
<style>
  .theme { --bg: #f4f1e9; --fg: #17160f; --accent: #2167c9; background: var(--bg); color: var(--fg); padding: 12px; font-family: sans-serif; }
  .theme.dark { --bg: #17160f; --fg: #f4f1e9; --accent: #ffd36b; }
  .btn { background: var(--accent); color: var(--bg); border: 0; padding: 8px 14px; border-radius: 8px; font-weight: 700; }
  .btn.danger { --accent: #e4402f; }
</style>
```

Так строятся темы (светлая/тёмная) и дизайн-системы: компоненты используют переменные, а значения меняются в одном месте.

## Методология БЭМ

БЭМ (Блок, Элемент, Модификатор) — соглашение об именах классов от Яндекса. Оно решает проблемы конфликтов и специфичности.

- **Блок** — независимый компонент: `.card`, `.menu`, `.search-form`;
- **Элемент** — часть блока, не существует отдельно: `.card__title`, `.card__image` (два подчёркивания);
- **Модификатор** — вариант или состояние: `.card--featured`, `.menu__item--active` (два дефиса).

```html
<article class="card card--featured">
  <img class="card__image" src="..." alt="...">
  <h3 class="card__title">Заголовок</h3>
  <a class="card__link card__link--disabled" href="#">Подробнее</a>
</article>
```

```css
.card { }
.card--featured { border-color: gold; }
.card__title { }
.card__link--disabled { opacity: .5; }
```

Правила: стилизуем **только классами**, без вложенности селекторов (`.card .title` — нельзя), без тегов и id. Тогда у всех селекторов одинаковая специфичность (0,1,0), и порядок в коде решает всё.

## Вложенность в CSS

Современный CSS поддерживает вложенность (раньше это было только в Sass):

```css
.card {
  padding: 16px;

  & h3 { margin: 0; }          /* .card h3 */
  &:hover { box-shadow: ...; }  /* .card:hover */
  &--featured { }               /* ✗ так нельзя! В нативном CSS & не склеивается со строкой */

  @media (min-width: 768px) {
    padding: 24px;
  }
}
```

> [!warn] Осторожно
> Не увлекайтесь вложенностью глубже 2–3 уровней — каждый уровень повышает специфичность, и мы возвращаемся к проблемам каскада.

## Сброс и нормализация

У браузеров есть собственные стили по умолчанию: отступы у `body`, `h1`, `ul`, разный вид кнопок. Чтобы начать с чистого листа, в начало CSS ставят небольшой **reset**:

```css
*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; line-height: 1.5; -webkit-font-smoothing: antialiased; }
img, picture, svg, video { display: block; max-width: 100%; }
input, button, textarea, select { font: inherit; }
p, h1, h2, h3 { overflow-wrap: break-word; }
```

## Организация файлов

Типичная структура стилей проекта:

```text
styles/
├── reset.css        — сброс
├── variables.css    — токены: цвета, шрифты, отступы
├── base.css         — стили тегов: body, a, h1…
├── components/      — блоки: button.css, card.css, header.css
└── utilities.css    — служебные: .visually-hidden, .container
```

Во Vue стили компонента живут прямо в его `.vue`-файле в блоке `<style scoped>` — БЭМ там нужен меньше, но переменные и reset остаются глобальными.
