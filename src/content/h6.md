Можно сверстать всю страницу из `<div>` — и она будет выглядеть нормально. Но для поисковиков, скринридеров и других разработчиков она будет «кашей». **Семантическая** разметка объясняет, *что* означает каждый блок.

## div и span — теги без смысла

- `<div>` — блочный контейнер «просто коробка»;
- `<span>` — строчный контейнер «просто кусочек текста».

Они нужны, когда подходящего смыслового тега нет: обёртка для раскладки, элемент для стилизации. Но если смысл есть — используйте смысловой тег.

## Семантические блоки страницы

```html
<body>
  <header>
    <a href="/">Логотип</a>
    <nav aria-label="Главное меню">…</nav>
  </header>

  <main>
    <article>
      <h1>Заголовок статьи</h1>
      <section>
        <h2>Раздел статьи</h2>
        <p>…</p>
      </section>
    </article>
    <aside>Похожие статьи</aside>
  </main>

  <footer>© 2026</footer>
</body>
```

| Тег | Смысл |
|---|---|
| `<header>` | Шапка страницы или раздела: логотип, заголовок, навигация |
| `<nav>` | Блок основной навигации |
| `<main>` | Главное содержимое. **Один** на странице |
| `<article>` | Самостоятельный материал: статья, пост, карточка товара, комментарий. Имеет смысл в отрыве от страницы |
| `<section>` | Тематический раздел с заголовком |
| `<aside>` | Дополнительное, «сбоку»: сайдбар, врезка |
| `<footer>` | Подвал страницы или раздела |
| `<address>` | Контактная информация |

> [!tip] Совет
> Простой тест для `article`: «Можно ли этот блок опубликовать отдельно, например в RSS?» Если да — `article`. Для `section`: «Есть ли у блока свой заголовок?» Если нет — скорее всего, нужен `div`.

## Почему это важно

1. **Доступность.** Скринридер умеет переходить сразу к `main`, `nav` — это называется «ориентиры» (landmarks). Слабовидящий пользователь не будет слушать меню на каждой странице.
2. **SEO.** Поисковики лучше понимают, где основной контент.
3. **Код читается.** `</article>` понятнее, чем десятый `</div>`.

## Доступность: базовые правила

Доступность (accessibility, a11y) — когда сайтом могут пользоваться все: с клавиатуры, со скринридером, с плохим зрением, на медленном интернете.

- **Правильный тег — лучшая доступность.** Кнопка — это `<button>`, а не `<div onclick>`: она фокусируется клавишей <kbd>Tab</kbd> и нажимается <kbd>Enter</kbd>/<kbd>Space</kbd> «из коробки».
- **Ссылка ведёт, кнопка действует.** Переход на другую страницу — `<a href>`. Действие на этой странице (открыть меню, отправить) — `<button>`.
- **У картинок — `alt`, у полей — `<label>`** (подробнее на станции «Формы»).
- **Порядок заголовков** без пропусков.
- **Язык** страницы в `<html lang="ru">`.
- Атрибуты **ARIA** (`aria-label`, `aria-expanded`…) дополняют HTML, когда тегов не хватает. Первое правило ARIA: не используйте ARIA, если можно обойтись родным тегом.

```html preview
<button type="button">Настоящая кнопка (попробуйте Tab)</button>
<div class="fake" onclick="alert('клик')">Ненастоящая кнопка-div</div>
<style>
  .fake { display: inline-block; padding: 2px 8px; border: 1px solid #999; margin-top: 8px; cursor: pointer; }
</style>
```

Нажмите в результате и походите <kbd>Tab</kbd>: на настоящую кнопку фокус попадает, на `div` — нет.

## Блочные и строчные элементы

По умолчанию элементы делятся на два типа отображения:

- **блочные** (`div`, `p`, `h1`, `ul`, `section`…) — занимают всю ширину, начинаются с новой строки;
- **строчные** (`span`, `a`, `strong`, `em`, `img`…) — идут в потоке текста.

Это поведение задаётся в CSS свойством `display`, и его можно изменить (станция «Блочная модель»).
