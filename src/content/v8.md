Пересадка с коричневой линии: здесь Vue встречается с Vite. В реальных проектах компоненты пишут в **однофайловых компонентах** (Single-File Components, SFC) — файлах `.vue`, где шаблон, логика и стили одного компонента лежат вместе. Vite с плагином `@vitejs/plugin-vue` превращает их в обычный JavaScript.

## Структура .vue-файла

```vue
<script setup>
import { ref } from 'vue'

const count = ref(0)
</script>

<template>
  <button class="counter" @click="count++">Нажато: {{ count }}</button>
</template>

<style scoped>
.counter {
  padding: 8px 16px;
  border-radius: 8px;
}
</style>
```

Три блока:

- `<script setup>` — логика компонента;
- `<template>` — шаблон (теперь с подсветкой и проверкой в редакторе, без строк в кавычках);
- `<style>` — стили; с атрибутом `scoped` они действуют **только** на этот компонент.

С этой станции задачи решаются в настоящих `.vue`-файлах — песочница компилирует их прямо в браузере так же, как Vite.

## script setup

`<script setup>` — сокращённая запись Composition API. Всё, что объявлено на верхнем уровне (переменные, функции, импорты), **автоматически доступно в шаблоне** — не нужен `return`:

```vue
<script setup>
import { ref, computed } from 'vue'
import StationCard from './StationCard.vue'   // импортированный компонент сразу можно использовать

const stations = ref([])
const count = computed(() => stations.value.length)

function add(name) {
  stations.value.push({ id: Date.now(), name })
}
</script>

<template>
  <StationCard v-for="s in stations" :key="s.id" :name="s.name" />
  <p>Всего: {{ count }}</p>
</template>
```

Сравните со станциями 1–7: нет `setup()`, `return`, `components: {}`. В шаблонах `.vue` можно писать компоненты в `PascalCase` и самозакрывающимися тегами.

## defineProps и defineEmits

В `<script setup>` props и события объявляются **макросами** — их не нужно импортировать:

```vue
<script setup>
const props = defineProps({
  name: { type: String, required: true },
  done: { type: Boolean, default: false },
})

const emit = defineEmits(['toggle', 'remove'])

function onClick() {
  emit('toggle', props.name)
}
</script>

<template>
  <li :class="{ done }" @click="onClick">{{ name }}</li>
</template>
```

В шаблоне пропсы доступны напрямую (`done`, `name`), в скрипте — через `props.`.

Для `v-model` на компоненте есть макрос `defineModel()`:

```vue
<script setup>
const model = defineModel()  // ref, связанный с v-model родителя
</script>

<template>
  <input v-model="model">
</template>
```

## Scoped-стили

```vue
<style scoped>
.title { color: green; }
</style>
```

Vue добавляет элементам компонента уникальный атрибут (например, `data-v-7ba5bd90`) и переписывает селектор в `.title[data-v-7ba5bd90]`. Поэтому `.title` в другом компоненте не пострадает. Стили без `scoped` — глобальные (подходят для `App.vue`: шрифты, сброс).

Чтобы из scoped-стилей достучаться до элемента дочернего компонента, используют `:deep()`:

```css
.list :deep(.item) { margin: 0; }
```

## Как устроен проект

```text
src/
├── main.js          ← createApp(App).mount('#app')
├── App.vue          ← корневой компонент
└── components/
    ├── TaskList.vue
    └── TaskItem.vue
```

```js
// main.js
import { createApp } from 'vue'
import App from './App.vue'
import './style.css'

createApp(App).mount('#app')
```

> [!tip] Именование
> Файлы компонентов называют в `PascalCase` и из двух слов (`TaskItem.vue`, не `Item.vue`), чтобы не путать с HTML-тегами. Базовые компоненты интерфейса часто начинают с `Base` или `App`: `BaseButton.vue`, `AppHeader.vue`.
