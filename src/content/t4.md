Vite работает «из коробки», но почти каждый проект его настраивает: подключает плагин Vue, задаёт алиасы путей, порт, прокси к API. Всё это — в файле **`vite.config.js`**. А секреты и адреса серверов, которые отличаются в разработке и продакшене, хранят в **переменных окружения**.

## vite.config.js

```js
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
  server: {
    port: 3000,
    open: true,
  },
})
```

`defineConfig` ничего не делает с объектом — он нужен редактору, чтобы подсказывать поля. Файл выполняется в **Node.js**, поэтому здесь доступны `node:url`, `node:path` и т. д.

## Плагины

Сам Vite не знает про `.vue`-файлы — их понимает официальный плагин `@vitejs/plugin-vue`. Плагины ставятся как dev-зависимости и подключаются в массив `plugins`:

```bash
npm install -D @vitejs/plugin-vue
```

Другие популярные: `vite-plugin-vue-devtools` (инструменты отладки), `@vitejs/plugin-legacy` (поддержка старых браузеров), `vite-plugin-pwa`.

## Алиасы путей

Без алиасов импорты из глубоко вложенных файлов превращаются в `../../../components/Button.vue`. Алиас `@` → `src` делает их короткими и устойчивыми к переносу файлов:

```js
import Button from '@/components/Button.vue'
import { formatDate } from '@/utils/date.js'
```

## Настройки dev-сервера

| Опция | Что делает |
|---|---|
| `server.port` | Порт (по умолчанию 5173) |
| `server.open` | Открыть браузер при старте |
| `server.host` | `true` — доступ из локальной сети (с телефона) |
| `server.proxy` | Перенаправлять запросы к API на другой сервер |

**Прокси** решает проблему CORS при разработке: фронтенд на `localhost:5173` обращается к `/api/...`, а Vite пересылает запрос на бэкенд:

```js
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true,
    },
  },
},
```

## Переменные окружения: .env

Адрес API в разработке и на боевом сервере разный. Чтобы не править код, значения выносят в файлы `.env`:

```bash
# .env — общие значения
VITE_APP_TITLE=Фронтенд метро

# .env.development — для npm run dev
VITE_API_URL=http://localhost:8080/api

# .env.production — для npm run build
VITE_API_URL=https://api.example.com
```

В коде они доступны через `import.meta.env`:

```js
const res = await fetch(`${import.meta.env.VITE_API_URL}/tasks`)

console.log(import.meta.env.MODE) // 'development' или 'production'
console.log(import.meta.env.DEV)  // true в dev-режиме
console.log(import.meta.env.PROD) // true в сборке
```

> [!warn] Важно
> В клиентский код попадают **только** переменные с префиксом `VITE_`. Это защита: переменная `DB_PASSWORD` не утечёт в браузер. Но помните: всё, что с `VITE_`, увидит любой пользователь в коде сайта. Настоящие секреты (ключи платёжных систем, пароли) во фронтенде хранить нельзя — только на сервере.

Файлы `.env.local` и `.env.*.local` предназначены для личных настроек и **не коммитятся** (они есть в `.gitignore`).

## Конфиг как функция

Если настройки зависят от режима, `defineConfig` принимает функцию:

```js
export default defineConfig(({ command, mode }) => ({
  plugins: [vue()],
  base: command === 'build' ? '/my-app/' : '/',
}))
```

`command` — `'serve'` (dev) или `'build'`, `mode` — `'development'`/`'production'` или свой (`vite build --mode staging`).
