**Git** — система контроля версий. Она хранит историю изменений проекта: можно посмотреть, кто и что поменял, откатиться к рабочей версии, параллельно вести несколько задач. Без Git сегодня не работает ни одна команда — и ни один деплой.

## Основные понятия

- **Репозиторий** — папка проекта, история которой отслеживается (служебная папка `.git`).
- **Коммит** — «снимок» состояния файлов с сообщением: что и зачем изменено.
- **Ветка** — независимая линия коммитов. Основная обычно называется `main`.
- **Удалённый репозиторий** (remote) — копия на сервере: GitHub, GitLab, Gitflic.

Файл проходит три состояния:

```text
рабочая папка ──git add──► индекс (staging) ──git commit──► история
  (изменили)               (подготовили)                    (сохранили)
```

## Первая настройка

```bash
git config --global user.name "Анна Петрова"
git config --global user.email "anna@example.com"
git config --global init.defaultBranch main
```

## Ежедневный цикл

```bash
git init                     # превратить папку в репозиторий (один раз)
git status                   # что изменилось — смотрите постоянно!
git add index.html           # добавить файл в индекс
git add .                    # добавить все изменения
git commit -m "Добавить форму обратной связи"
git log --oneline            # история коммитов
git diff                     # что именно изменилось (до add)
```

> [!tip] Совет
> Хорошее сообщение коммита отвечает на вопрос «что сделает этот коммит?»: «Добавить фильтр задач», «Исправить отступы в шапке». Коммитьте часто и маленькими логическими порциями.

## .gitignore

Не всё нужно хранить в Git. Файл `.gitignore` перечисляет, что игнорировать:

```text
node_modules
dist
.env
.env.local
.DS_Store
*.log
```

`node_modules` и `dist` восстанавливаются командами, а `.env` может содержать секреты.

## Ветки

```bash
git switch -c feature/todo-filter   # создать ветку и перейти в неё
# ... работаем, коммитим ...
git switch main                     # вернуться в main
git merge feature/todo-filter       # влить изменения ветки в main
git branch -d feature/todo-filter   # удалить ветку
```

Работа в ветках позволяет не ломать `main`: новая функция разрабатывается отдельно и вливается, когда готова. В командах вливание делают через **Pull Request** (Merge Request) — с ревью кода.

**Конфликт** возникает, когда две ветки изменили одни и те же строки. Git помечает их в файле маркерами `<<<<<<<`, `=======`, `>>>>>>>` — нужно вручную выбрать правильный вариант, удалить маркеры и закоммитить.

## Работа с GitHub

```bash
git clone https://github.com/user/repo.git   # скачать репозиторий
git remote add origin https://github.com/user/repo.git
git push -u origin main                      # отправить коммиты на сервер
git pull                                     # забрать чужие изменения
```

## Отмена изменений

```bash
git restore index.html          # отменить незакоммиченные правки файла
git restore --staged index.html # убрать из индекса (правки останутся)
git commit --amend              # поправить последний коммит (если ещё не запушен)
git revert <хэш>                # создать коммит, отменяющий указанный
```

> [!warn] Осторожно
> Команды `git reset --hard` и `git push --force` безвозвратно стирают изменения. Используйте их, только понимая последствия, и никогда — на общих ветках.
