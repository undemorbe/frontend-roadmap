Многие операции не завершаются мгновенно: запрос к серверу, таймер, чтение файла. JavaScript не ждёт их, «замерев», — он продолжает работать, а результат обрабатывает **потом**. Это асинхронность, и без неё не обходится ни одно реальное приложение.

## Один поток и цикл событий

JavaScript в браузере выполняется в **одном потоке**: в каждый момент выполняется ровно одна строка кода. Если бы запрос к серверу блокировал поток на 2 секунды, страница бы «замёрзла» — не реагировала бы на клики и прокрутку.

Поэтому долгие операции выполняет браузер «в фоне», а когда они готовы, колбэк ставится в **очередь**. **Цикл событий** (event loop) берёт задачи из очереди, когда основной код закончил работу.

```js preview
console.log('1. Начало')

setTimeout(() => {
  console.log('3. Таймер (даже с задержкой 0!)')
}, 0)

console.log('2. Конец синхронного кода')
```

## Таймеры

```js
const id = setTimeout(() => console.log('через 1 с'), 1000)
clearTimeout(id)                          // отменить

const tick = setInterval(() => console.log('каждую секунду'), 1000)
clearInterval(tick)                       // остановить
```

## Промисы

Колбэки внутри колбэков быстро превращаются в «ад колбэков». Решение — **Promise** (обещание): объект, представляющий результат, который будет получен в будущем.

У промиса три состояния: **pending** (ожидание) → **fulfilled** (выполнен, есть результат) или **rejected** (отклонён, есть ошибка).

```js
function wait(ms) {
  return new Promise((resolve) => {
    setTimeout(resolve, ms)
  })
}

function loadUser(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id > 0) resolve({ id, name: 'Аня' })
      else reject(new Error('Неверный id'))
    }, 500)
  })
}

loadUser(1)
  .then((user) => console.log(user.name))    // успех
  .catch((err) => console.error(err.message)) // ошибка
  .finally(() => console.log('Готово'))      // в любом случае
```

`.then` возвращает новый промис, поэтому их можно соединять в цепочки.

## async / await

Современный и самый читаемый способ работать с промисами:

```js
async function showUser() {
  try {
    const user = await loadUser(1)    // «подождать» результат промиса
    console.log(user.name)
  } catch (err) {                     // rejected → сюда
    console.error(err.message)
  } finally {
    console.log('Готово')
  }
}
```

- `async` перед функцией: она **всегда** возвращает промис;
- `await` приостанавливает выполнение **этой функции** (не всей страницы!) до готовности промиса;
- ошибки ловятся обычным `try...catch`.

```js preview
const wait = (ms) => new Promise((r) => setTimeout(r, ms))

async function countdown() {
  for (let i = 3; i > 0; i--) {
    console.log(i)
    await wait(400)
  }
  console.log('Поехали! 🚇')
}

countdown()
console.log('Этот лог появится сразу — countdown не блокирует код')
```

## Параллельно, а не по очереди

```js
// ✗ медленно: второй запрос стартует после первого
const a = await loadUser(1)
const b = await loadUser(2)

// ✓ быстро: оба запроса одновременно
const [a, b] = await Promise.all([loadUser(1), loadUser(2)])
```

- `Promise.all` — ждёт все; отклоняется, если упал хотя бы один;
- `Promise.allSettled` — ждёт все, возвращает статус каждого;
- `Promise.race` / `Promise.any` — первый завершившийся / первый успешный.

## Обработка ошибок

```js
try {
  JSON.parse('{ сломано')
} catch (err) {
  console.error(err.name, err.message)   // SyntaxError ...
}

throw new Error('Что-то пошло не так')    // бросить свою ошибку
```

Необработанный отклонённый промис выдаст в консоль `Uncaught (in promise)`. Всегда ловите ошибки асинхронных операций — и показывайте пользователю понятное сообщение.
