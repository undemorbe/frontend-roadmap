Сайт обычно состоит из нескольких страниц. В **одностраничном приложении** (SPA) браузер загружает HTML один раз, а смену «страниц» делает JavaScript: меняет адрес и показывает другой компонент — без перезагрузки. Этим занимается **Vue Router** — официальный маршрутизатор Vue.

## Установка и настройка

```bash
npm install vue-router
```

```js
// router.js
import { createRouter, createWebHistory } from 'vue-router'
import HomeView from './views/HomeView.vue'

export const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', name: 'home', component: HomeView },
    { path: '/about', name: 'about', component: () => import('./views/AboutView.vue') },
  ],
})
```

```js
// main.js
import { createApp } from 'vue'
import App from './App.vue'
import { router } from './router.js'

createApp(App).use(router).mount('#app')
```

`component: () => import(...)` — **ленивая загрузка**: код страницы скачается, только когда пользователь на неё перейдёт. Vite вынесет его в отдельный файл.

## Режимы истории

| Режим | Адрес | Особенность |
|---|---|---|
| `createWebHistory()` | `/about` | Красивые адреса, но сервер должен отдавать `index.html` на все пути |
| `createWebHashHistory()` | `/#/about` | Работает на любом хостинге без настройки |
| `createMemoryHistory()` | адрес не меняется | Для тестов и SSR — его мы используем в песочнице |

## RouterLink и RouterView

```vue
<template>
  <nav>
    <RouterLink to="/">Главная</RouterLink>
    <RouterLink :to="{ name: 'about' }">О проекте</RouterLink>
  </nav>

  <RouterView />   <!-- сюда подставится компонент текущего маршрута -->
</template>
```

`RouterLink` рендерит обычный `<a>`, но перехватывает клик и меняет страницу без перезагрузки. Активной ссылке автоматически добавляется класс `router-link-active` (и `router-link-exact-active` при точном совпадении) — удобно для подсветки меню.

## Динамические маршруты

```js
{ path: '/station/:id', name: 'station', component: StationView }
```

```vue
<!-- StationView.vue -->
<script setup>
import { computed } from 'vue'
import { useRoute } from 'vue-router'

const route = useRoute()
const id = computed(() => route.params.id)   // '/station/42' → '42' (строка!)
</script>

<template>
  <h1>Станция {{ id }}</h1>
</template>
```

> [!tip] Совет
> При переходе с `/station/1` на `/station/2` Vue **переиспользует** тот же компонент — `setup` не выполнится заново. Поэтому параметры читают через `computed` или `watch(() => route.params.id, ...)`.

Также доступны `route.query` (`?sort=name` → `{ sort: 'name' }`) и `route.hash`.

## Программная навигация

```js
import { useRouter } from 'vue-router'

const router = useRouter()

router.push('/about')
router.push({ name: 'station', params: { id: 7 } })
router.push({ path: '/search', query: { q: 'flex' } })
router.replace('/login')  // без записи в историю
router.back()
```

## Страница 404

Маршрут-«ловушка» ставят последним:

```js
{ path: '/:pathMatch(.*)*', name: 'not-found', component: NotFoundView }
```

## Навигационные хуки (guards)

`beforeEach` вызывается перед каждым переходом. Типичная задача — закрыть страницы от неавторизованных пользователей:

```js
const routes = [
  { path: '/profile', component: ProfileView, meta: { requiresAuth: true } },
  { path: '/login', component: LoginView },
]

router.beforeEach((to) => {
  if (to.meta.requiresAuth && !auth.isLoggedIn) {
    return { path: '/login', query: { redirect: to.fullPath } }
  }
  // ничего не вернули — переход разрешён
})
```

## Вложенные маршруты

```js
{
  path: '/lines/:line',
  component: LineLayout,           // внутри — свой <RouterView />
  children: [
    { path: '', component: LineOverview },
    { path: 'stations', component: LineStations },  // /lines/css/stations
  ],
}
```
